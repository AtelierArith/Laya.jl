Laya — Module
Laya

Pure-Julia inference for Laya typed-decision models, ported from laya-mlx.

Loading and prediction

Laya.load — Function
load(model_id_or_path="convaiinnovations/laya"; dtype=Float32, batch_size=16, subfolder=nothing,
     revision=nothing, backend=CPUBackend())

Load a Laya checkpoint (local directory or Hugging Face repository, downloaded on first use; see resolve_model). The tokenizer, prompts and calibration always run in Julia; the model forward runs on backend (see Backend).

source
Laya.predict — Function
predict(agent, state, questions) -> JSON.Object

Answer typed questions about state (a string, or a dictionary/vector serialized as JSON). questions maps question ids to Dict("type" => "choice"|"score"|"noul", "instructions" => ..., "criteria" => ...). The result mirrors upstream Laya: model, answers (per question: type, confidence, action.act_probability, and choice/score/noul fields) and usage.

source
Laya.system_one — Function
system_one(agent, state, questions) -> JSON.Object

The same as predict, under upstream Laya's name.

source
Laya.Agent — Type
Agent

A loaded Laya checkpoint: tokenizer, model and calibration. Create with load. model is whatever the backend loaded (a DecisionModel on the CPU).

source
Laya.resolve_model — Function
resolve_model(model_id_or_path; subfolder=nothing, revision=nothing) -> String

A local checkpoint directory, or a Hugging Face repository. A repository is looked up in the Hugging Face cache (HF_HUB_CACHE, HF_HOME/hub or ~/.cache/huggingface/hub, shared with Python), then in Laya's scratch space, and otherwise downloaded into the scratch space (disabled when HF_HUB_OFFLINE is set); only the checkpoint files are fetched (see hub_download). HF_TOKEN is sent for private repositories.

source
Laya.hub_download — Function
hub_download(repo, revision="main"; subfolder=nothing) -> String

Download the checkpoint files of the Hugging Face model repository repo at revision (model.safetensors, rl_agent_config.json, encoder/config.json, mlx_config.json and tokenizer/, inside subfolder if given) into Laya's scratch space and return the snapshot directory. Other files, such as further checkpoints in other subfolders, are skipped. Each file appears in the snapshot only once completely downloaded; files already there are kept.

Backends

Laya.Backend — Type
Backend

Supertype of Laya's own backends. Pass a backend to load as backend:

backendruns onneeds
CPUBackend()CPU, Julia's current BLAS–
AccelerateBackend()CPU, Apple Accelerate BLASusing AppleAccelerate
MetalBackend()Apple GPU (Metal.jl's backend type)using Metal
LayaMLX.MLXBackend()Apple GPU via MLXthe LayaMLX package

A new backend only needs a method of load_backend_model for its type.

source
Laya.CPUBackend — Type
CPUBackend()

The pure-Julia DecisionModel on the CPU with whatever BLAS Julia currently uses (OpenBLAS by default). Start Julia with -t auto for threaded attention and normalization.

source
Laya.AccelerateBackend — Type
AccelerateBackend()

CPUBackend with BLAS forwarded to Apple's Accelerate framework (3-5× faster matrix products on Apple silicon). Requires using AppleAccelerate. The forwarding is process-wide, so every CPU model in the process uses Accelerate afterwards.

source
Laya.load_backend_model — Function
load_backend_model(backend, dir, dtype) -> model

Load the checkpoint in dir with element type dtype for backend. model(batch) takes a collated batch and returns host Arrays logits (K, n) and action (A, n), like DecisionModel.

Model

Laya.DecisionModel — Type
DecisionModel{T}

The Laya network: a ModernBERT encoder, the decision-head Transformer layers, the option scorer and the action head, with parameters of element type T. Load one with load_model (or through load); call it on a collated batch. Its weights may live in any array type (see adapt_arrays).

source

load_model(dir; dtype=Float32) -> (model, encoder_config, agent_config)

Load model.safetensors, encoder/config.json and rl_agent_config.json from a Laya checkpoint directory (upstream or MLX-converted).

Array-generic building blocks

The model code is written against AbstractArray; device backends move the weights and specialize these by array type.

Laya.adapt_arrays — Function
adapt_arrays(to, model) -> model

model with every weight array replaced by to(array) (e.g. Metal.MtlArray), keeping the structure and configuration; device backends use it to move a CPU-loaded model.

on_device_of(ref, x) -> array

x (a host array) in the same kind of array as ref: x itself when ref is an Array.

Laya.to_host — Function

x as a host Array (no copy when it already is one).

Laya.gather_columns — Function

E[:, idx] for a host index vector idx, on E's device.

Laya.release! — Function
release!(arrays...)

Hint that intermediate arrays are no longer used. A no-op for host arrays; device backends return the memory to their pool at once (Julia's GC does not see device memory pressure).

source
Laya.residual_norm — Function
residual_norm(x, y, ln) -> (z, ln(z))

The residual sum z = x .+ y and its normalization, freeing y. Device backends fuse both into one kernel.

source
Laya.qkv_attention — Function
qkv_attention(qkv, heads, rope_base, mask, scale) -> (d, L, B)

Multi-head self-attention from the fused projection qkv (3d, L, B) ([q; k; v] along the first axis), with RoPE on q and k unless rope_base === nothing. The unit that device backends specialize (e.g. one fused kernel for the split, RoPE and head layout).

source
Laya.AttentionMask — Type
AttentionMask(dense, valid, window)

A key mask for self-attention. dense is the Bool mask (L_k, L_q, B) (or (L_k, 1, B)) that the generic code applies; valid (L, B) marks real (unpadded) tokens and window is the half-width of local attention (nothing for global attention). Together they describe dense: a valid query keeps the valid keys within window of it, a padded query keeps all valid keys. Kernels use the structure to skip masked blocks.

source
Laya.attention — Function
attention(q, k, v, mask, scale)

Scaled dot-product attention for q, k, v of size (head_dim, heads, L, B). mask is a Bool array broadcastable to (L_k, L_q, B); true keeps a key. Returns (head_dim, heads, L, B).

source
Laya.rope — Function
rope(x, base)

Non-traditional RoPE (mx.fast.rope(..., traditional=False, scale=1, offset=0)) on x of size (head_dim, heads, L, B): the first and second halves of each head are rotated as pairs, with angle position * base^(-2i / head_dim).
